Handling Missing Values
The most common problem in real-world data

📖 Why Data is Missing

  • MCAR — Missing Completely At Random (user skipped a form field)
  • MAR — Missing At Random (older users skip tech questions)
  • MNAR — Missing Not At Random (high earners hide income)

Strategies:

❌ Drop Row
Use only if <5% of data is missing and it's random
✅ Impute
Fill with mean/median (numeric) or mode (categorical)
🤖 ML Impute
Predict missing values using another ML model (KNN Imputer)
🏷️ Flag It
Add a new column: "age_was_missing = 1/0"

⚖️ Feature Scaling Explained

Without scaling, a salary of $100,000 will completely dominate an age of 25 purely because the number is 4000× bigger. The model will think salary matters infinitely more than age!

StandardScaler (Z-score)
z = (x − mean) / std
Output: mean=0, std=1. Best for algorithms that assume normal distribution (Linear Regression, SVM).
MinMaxScaler
x' = (x − min) / (max − min)
Output: range [0, 1]. Best for Neural Networks and KNN.
📏 The Ruler Analogy Scaling is like converting all measurements to the same unit. You can't compare a race time in seconds with a distance in kilometres — you need a common scale!
Module 4A

Logistic Regression — Classification with Probability

Despite its name, Logistic Regression is a Classification algorithm — not Regression!

📖 How It Works

Logistic Regression predicts the probability that something belongs to a class. Instead of predicting a number (like Linear Regression), it maps any input to a value between 0 and 1 using the Sigmoid Function.

Sigmoid: σ(z) = 1 / (1 + e^(−z))
If σ(z) ≥ 0.5 → Class 1 (Spam, Fraud, Yes)
If σ(z) < 0.5 → Class 0 (Not Spam, Normal, No)
🌡️ The Thermometer Analogy Linear Regression gives you the temperature (any number). Logistic Regression is like a fever test: it tells you if the temperature is "Normal" (0) or "Fever" (1). The sigmoid squishes any temperature into that 0-1 scale.

✉️ Real IT Scenario: Email Spam Detection — predict probability (0–100%) that an email is spam. If >50%, move it to spam folder.

📊 Sigmoid Curve — Logistic Regression's Secret Weapon

🧮 Step-by-Step Hand Calculation: From Linear Score to Probability & Cross-Entropy Penalty

Here is the exact numerical path from raw features to binary fraud verdict and model punishment:

Step 1: Compute Linear Score \(z\)

Features: \(X_1 = 5\text{ failed logins}\), \(X_2 = \$900\)
Weights: \(w_1 = 0.4, w_2 = 0.001, b = -1.5\)
\(z = 0.4(5) + 0.001(900) - 1.5 = \mathbf{1.386}\)

Step 2: Squish into Probability \(\sigma(z)\)

\(\sigma(1.386) = \frac{1}{1 + e^{-1.386}} = \frac{1}{1 + 0.25} = \mathbf{0.80}\)
80% Probability of Fraud \(\to\) Alert Triggered!

Step 3: If Actual \(y = 1\) (True Fraud)

\(\text{Loss} = -\ln(0.80) = \mathbf{0.223}\)
Tiny Loss: The model was confident and right!

Step 4: If Actual \(y = 0\) (False Alarm)

\(\text{Loss} = -\ln(1 - 0.80) = -\ln(0.20) = \mathbf{1.609}\)
7.2x Higher Penalty: Confident wrong answers are punished harshly!

Module 4B

Support Vector Machine (SVM)

Find the best boundary between classes by maximising the margin — one of the most powerful classifiers.

📖 The Core Idea — Maximise the Margin

SVM finds a hyperplane (a line in 2D, a plane in 3D) that best separates classes. Unlike Logistic Regression which just finds any boundary, SVM finds the one that maximises the gap (margin) between the two classes.

1

Find the data points closest to the boundary — these are called Support Vectors

2

Draw the boundary (hyperplane) that is equidistant from both classes' support vectors

3

The gap between support vectors and the hyperplane is the Margin

4

SVM maximises this margin → more margin = better generalisation on new data

🌀 The Kernel Trick What if data isn't linearly separable? SVM uses a Kernel Function to map data into a higher dimension where a hyperplane CAN separate it. Think of crumpling a flat piece of paper (2D data) and cutting it — that cut in 3D is the hyperplane!

🧬 Real IT Scenario: Medical image classification — SVM can classify tumour images as benign or malignant even with small datasets.

Module 4C

K-Nearest Neighbours (KNN)

The simplest algorithm in ML — "You are who your neighbours are."

📊 Visual: KNN with K=3

📖 How KNN Works

KNN is a lazy learner — it doesn't learn a model. Instead, when a new point arrives, it:

1

Calculates the distance between the new point and every training point (using Euclidean distance)

2

Finds the K closest training points (neighbours)

3

Takes a majority vote among those K neighbours

4

Assigns the new point to the winning class

Euclidean Distance:
d = √[(x₂−x₁)² + (y₂−y₁)²]
Small K → Complex boundary (overfit)
Large K → Simple boundary (underfit)
Best K → Use Cross-Validation!
🏘️ The Neighbourhood Analogy If you move to a new city and want to know what restaurants are good nearby, you ask your 5 nearest neighbours. If 4 of them recommend Italian and 1 recommends Thai — you try Italian! That's KNN.

🎬 Real IT Scenario: Netflix recommendation system — find the K most similar users to you, and recommend the movies those users liked.

🐳 Docker — Why It Matters for ML

📉 Data Drift — The Silent Killer

After deploying your model, the real world keeps changing. Data Drift is when the distribution of incoming data starts to differ from your training data — causing your model's accuracy to silently drop.

🔴 Feature Drift
Input data distribution changes. e.g., Your model was trained on pre-COVID travel data. Post-COVID, travel patterns are completely different!
🟡 Concept Drift
The relationship between features and labels changes. e.g., The words that indicate spam emails change over time as spammers adapt.
🟢 Solution — Monitor & Retrain
Track metrics weekly. Set alerts if accuracy drops below threshold. Retrain the model on fresh data on a schedule (daily/weekly/monthly).

# monitor.py — Track Model Performance in Production

import pandas as pd
import numpy as np
from scipy import stats
import joblib, logging

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)

def check_data_drift(train_data: pd.DataFrame, new_data: pd.DataFrame):
    """
    Compare statistical distributions between training data 
    and new incoming data. If they diverge, trigger a retrain.
    """
    drift_detected = False
    
    for col in train_data.columns:
        # Kolmogorov-Smirnov test: checks if two distributions are the same
        ks_stat, p_value = stats.ks_2samp(train_data[col], new_data[col])
        
        if p_value < 0.05:  # p < 0.05 means significant difference!
            logger.warning(f"⚠️  DRIFT DETECTED in '{col}': p={p_value:.4f}")
            drift_detected = True
        else:
            logger.info(f"✓ '{col}' distribution: stable (p={p_value:.4f})")
    
    return drift_detected

def monitor_accuracy(threshold: float = 0.85):
    # Load last week's predictions + actual outcomes
    df = pd.read_csv('logs/predictions_last_7_days.csv')
    current_accuracy = (df['prediction'] == df['actual']).mean()
    
    logger.info(f"Current 7-day accuracy: {current_accuracy:.2%}")
    
    if current_accuracy < threshold:
        logger.error(f"🚨 ACCURACY BELOW THRESHOLD! {current_accuracy:.2%} < {threshold:.2%}")
        trigger_retrain()  # Automatically kick off retraining!

if __name__ == "__main__":
    train_df = pd.read_csv('data/training_data.csv')
    live_df  = pd.read_csv('data/last_7_days.csv')
    
    check_data_drift(train_df, live_df)
    monitor_accuracy(threshold=0.85)
Advanced Interview Prep

Hard Interview Questions — Expert Answers

These questions are asked in senior/mid-level Data Science roles. Know them and you will stand out.

What is the Kernel Trick in SVM and why is it needed?
In real data, classes are often not linearly separable — you can't draw a straight line to separate them. The Kernel Trick is a mathematical technique that maps data from a lower-dimensional space to a higher-dimensional space where a hyperplane CAN separate the classes.

For example, data arranged in concentric circles (not linearly separable in 2D) can be separated by adding a third dimension (Z = X² + Y²), making it perfectly separable by a flat plane.

Common Kernels: Linear (no transformation), RBF/Gaussian (most common, handles circular boundaries), Polynomial (for polynomial boundaries).

The trick is that the algorithm never explicitly computes the high-dimensional space — it only computes the dot products, making it computationally efficient.
Why does KNN get slow with large datasets? What are the alternatives?
KNN's prediction time scales as O(n × d) where n is the number of training samples and d is the number of dimensions. For 10 million samples, every single prediction requires computing distance to 10 million points — extremely slow.

Solutions:
• KD-Tree: Organises data in a tree structure, reducing search from O(n) to O(log n). Efficient for low dimensions (<20).
• Ball Tree: Better than KD-Tree for high-dimensional data.
• Approximate Nearest Neighbours (ANN): Libraries like Faiss (by Facebook) or Annoy (by Spotify) trade a tiny bit of accuracy for massive speed gains — used in production recommendation systems.
• Alternative: If KNN is too slow, consider switching to Random Forest or a trained Neural Network for faster inference.
What is XGBoost and why does it outperform standard Gradient Boosting?
XGBoost (Extreme Gradient Boosting) improves on standard Gradient Boosting in several key ways:

1. Regularisation (L1 + L2): XGBoost has built-in regularisation that prevents overfitting — standard Gradient Boosting doesn't.
2. Parallelisation: Building each tree is parallelised across CPU cores, making it much faster.
3. Tree Pruning: Uses "max_depth" pruning strategy instead of stopping early, building deeper trees then pruning back.
4. Handling Missing Values: Automatically learns which direction to assign missing values — no imputation needed!
5. Cache Optimisation: Designed for modern CPU cache architecture.

Interview Rule: For any structured/tabular data problem, try XGBoost first. It wins most Kaggle competitions involving tabular data.
Explain how you would handle a class imbalance problem (e.g., 99% Normal, 1% Fraud).
Never just "do nothing" — the model will ignore the minority class. Here are the strategies:

Data-Level Solutions:
• Oversampling: Duplicate minority class samples (simple but can overfit)
• SMOTE (Synthetic Minority Over-sampling Technique): Creates synthetic samples between existing minority samples — much better than simple duplication
• Undersampling: Remove majority class samples to balance (loses information)

Algorithm-Level Solutions:
• Use class_weight='balanced' in sklearn — automatically adjusts weights inversely proportional to class frequency
• In XGBoost: use scale_pos_weight = count(negative)/count(positive)

Evaluation:
• Never use Accuracy. Use Precision, Recall, F1-Score, and ROC-AUC.
• For extreme imbalance (0.1%), use Precision-Recall AUC instead of ROC-AUC.
What happens when you deploy a model and its accuracy starts dropping after 3 months?
This is the Data Drift / Concept Drift problem — one of the most important things to understand for production ML.

Step 1 — Diagnose:
• Check your monitoring dashboards for accuracy trends
• Run a Kolmogorov-Smirnov test or Population Stability Index (PSI) to compare the distribution of incoming features vs. training data
• Check if the label distribution has changed (concept drift)

Step 2 — Solutions:
• Retrain: Collect new labelled data and retrain the model (most reliable)
• Continuous Learning: Set up an automated pipeline that retrains on a rolling window of recent data (e.g., last 90 days)
• Model Ensembling: Blend old model with a new model trained on recent data

Step 3 — Prevent:
• Set up automated monitoring with alerts (accuracy below threshold triggers retrain pipeline automatically)
• Store all predictions and ground truth labels for analysis
